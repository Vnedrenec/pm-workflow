> Стадия постановки, класс `гигиена`. Автор — Architect, 2026-09-18. Аудит постановки —
> один круг (Reviewer), правка — одной стадией, дальше стадия кода (Builder, один круг
> аудита кода). Решение владельца: 2026-09-18, реквизит D-9 в приватном реестре (§6.3).
> Архитектурное решение — `docs/adr/0002-public-repository-sanitization.md`.
>
> Написано для исполнителя, который не видит ни чата, ни трекера. Всё нужное — в этом
> файле, в файлах по путям и в теле его подзадачи (там — адреса репозиториев и чек-лист
> конфиденциального от владельца; здесь они не называются — постановка сама обязана
> проходить свой сторож). Этот файл в архивном дереве носит имя со слагом карточки;
> в публичном дереве переименовывается (§5).

## 0. Что не так — с доказательством

Регламент должен доставляться скиллами через `multica skill import --url`, а импорт работает только с публичного GitHub. Репозиторий приватный, и в нём внутренняя кухня. Инвентаризация 2026-09-18 (регулярные выражения — §6.4; собранная копия `skills/pm-workflow/references/` не считалась — она воспроизводится сборкой):

| Категория | Строк в дереве | Добавленных строк в истории (`git log --all -p`, 11 коммитов) |
|---|---|---|
| проект / организация / трекер проекта | 79 | 216 |
| идентификатор карточки трекера (четыре префикса) | 140 | 357 |
| ссылка на приватный документ / репозиторий / учётную запись | 77 | 207 |
| персона / имя агента / имя подписки | 20 | 39 |
| id: UUID карточек, комментариев, агентов, скиллов; короткие id рантаймов | 64 | 132 |
| **итого строк (строка может попасть в несколько категорий)** | **260** | **635** |

Из 260 строк: 130 — исходная постановка о выносе регламента, 7 — снимок инструкций PM, 7 — заметки воркспейса (три файла уходят целиком, §4); 23 — резолвер инцидентов (переписывается целиком, §6.1); 31 — `CHANGELOG.md`; 62 — точечные правки в правилах, ADR, автопилотах, шаблонах, скилле слоя 1, скриптах. Полный список `файл:строка · категория · действие` — приложение А. Ни одного коммита без стоп-слов в истории нет: первый содержательный коммит — постановка с идентификаторами. Имя одного файла содержит слаг карточки. Все 11 коммитов — с личным e-mail автора.

## 1. Инвариант

**В публичном дереве и в публичной истории нет ни одного стоп-слова — по построению, а не по дисциплине; каждое правило сохраняет основание (симптом · следствие) и каждый обход — условие снятия; соответствие обезличенного инцидента реальной карточке существует, но вне публичного репозитория.**

## 2. Решение и альтернативы

Полный разбор — ADR 0002. Кратко:

| Вопрос | Выбрано | Отвергнуто | Почему |
|---|---|---|---|
| История git | новый репозиторий с одним коммитом; старый переименовывается, архивируется, остаётся приватным; новый получает прежнее имя | (а) `git filter-repo` + force-push; (б) orphan-ветка + force-push; (в) новый репозиторий под другим именем | (а), (б): GitHub оставляет старые коммиты достижимыми через `refs/pull/N/head` трёх смерженных PR и по SHA — после публикации это утечка, которую изнутри не проверить; (в): меняются адрес в реестре воркспейса и URL импорта скиллов |
| Идентификаторы инцидентов | буквы `A`…`Z`, `AA`…; якорь `inc-<буква>`; публично — симптом · следствие · правило; приватно — карточка, дата, первичная запись | оставить номера без префикса; дата как ключ | номер без префикса бесполезен читателю; дата — «сроки» из чек-листа владельца и не уникальна |
| Реквизиты решений владельца | `D-N` + дата в `CHANGELOG.md`; карточка и id комментария — в приватной таблице | оставить id комментариев | UUID — идентификатор трекера воркспейса |
| Словарь стоп-слов | публичная структурная часть в репозитории + приватная литеральная часть в приватном реестре, в CI — секретом | один публичный файл с названиями | публичный файл с названиями проектов и людей — сам утечка |
| Сторож | в `scripts/check-rules.sh`: дерево, имена файлов, заголовок PR, сообщения коммитов диапазона, вся история (в новом репозитории); печатает `файл:строка` и номер шаблона, не текст | печатать совпавший текст | логи Actions публичного репозитория читают все |
| Снимок инструкций PM и исходная постановка | остаются в приватном архиве (старый репозиторий); в публичном — запись `CHANGELOG.md`, где лежат | обезличить исходную постановку (130 строк из 722) | текст о внутренней работе проекта-источника; после замены не станет методикой; решение уже зафиксировано в ADR 0001 |
| Заметки воркспейса (`workspace-notes.md`) | в приватный реестр; в публичном — нет | обезличить плейсхолдерами | это операционный текст для конкретного воркспейса: адреса, id агента; читатель один — PM |
| Имена моделей провайдеров | остаются как классы моделей (`gpt-*`, `glm-*`, `grok-*`, `gemini-*`, `Claude`) | убрать | владелец: обозначения моделей как классов — не конфиденциально; убираются только имена подписок/тарифов |
| Имена скиллов вне репозитория (`test-guard-discipline`, `project-bootstrap-checklist`, `audit-run-hygiene`) | остаются как названия методических приёмов | заменить описанием | названия не несут ни проекта, ни организации; идентификаторы (UUID) скиллов убираются |
| Даты решений владельца и условий снятия | остаются | убрать | без дат `CHANGELOG.md` не упорядочить, а условия снятия раздела B — не проверить; дата решения не раскрывает деятельность |

## 3. Границы

**Делается:** обезличивание дерева по §4–§6; сторож и словари; приватный резолвер и приватный словарь в приватном реестре; перенос заметок воркспейса; новый репозиторий с одним коммитом; перерегистрация кэша checkout.

**Не делается:** изменение правил по существу (ни одно правило не добавляется, не удаляется, не меняет условие — число строк `docs/rule-index.tsv` = 70 до и после; меняются только строки из приложения А и ссылки на удалённые файлы); публикация (visibility → public — операция владельца после `done` родителя); импорт скиллов (отдельная карточка после публикации); правка регламента проекта-источника (слой 3) и его постановок; чистка других репозиториев воркспейса.

## 4. Категории конфиденциального и правила замены

Чек-лист владельца — в теле подзадачи исполнителя. Категории и форма замены в публичном тексте:

| Категория | Примеры (классом, не значением) | Что делать | Форма в публичном тексте |
|---|---|---|---|
| проект, продукт, организация | название проекта-источника; название трекера проекта; название воркспейса; префиксы карточек как имена проектов | заменить | «проект», «проект-источник», «трекер проекта», «воркспейс»; путь файла проекта — без имени проекта (`docs/engineering/pm-workflow.md` проекта) |
| идентификатор карточки, комментария, PR, скилла, агента, рантайма, воркспейса, пользователя | `ПРЕФИКС-N`, UUID, `владелец/репозиторий#N`, короткий hex-id | вынести в приватный резолвер; в тексте — буква инцидента или `D-N`; для скиллов/агентов — плейсхолдер `<id скилла>`, `<agent-id>` | `[B](incidents.md#inc-b)`, `D-8`, `<id agent-runtime-gotchas>` |
| ссылка на приватный документ или репозиторий, учётная запись GitHub, e-mail | файл уроков проекта, приватный реестр, репозиторий оценок по URL, архив инструкций | заменить | «приватный реестр воркспейса», «репозиторий оценок (описание `scorecard` в `multica repo list`)», «файл уроков проекта-источника», `<URL этого репозитория>` |
| персона: имена людей, имена агентов, имена подписок | владелец по имени; агенты с именем и суффиксом модели; тариф провайдера | заменить | «владелец»; роль (`PM`, `Architect`, `Reviewer`, `Builder`, `Mechanic`) + при необходимости класс модели; модель без тарифа |
| деталь деятельности организации | сроки, клиенты, суммы, внутренние процессы вне конвейера | удалить | — (замеры конвейера — числа кейсов, минуты простоя, токены — остаются: это доказательство правила, не деятельность) |
| ложные срабатывания | `mention://agent/<id>` как синтаксис платформы; `<agent-id>`; модели провайдеров; `scorecard` как термин | оставить | как есть |

Правило для будущего: новый инцидент — новая буква и две строки (публичная в `docs/incidents.md`, приватная в резолвере); новое решение владельца — новый `D-N` (публично дата и номер, приватно карточка и комментарий); новое имя — строка в приватный словарь и обновление секрета (§6.5). Записывается в `README.md` («Как ссылаться на инцидент», «Как править»).

## 6. Форматы

### 6.1. Публичный `docs/incidents.md`

Шапка: «Один адрес на инцидент. Идентификатор — буква (после `Z` — `AA`, `AB`, …), якорь `inc-<буква в нижнем регистре>`. Соответствие буквы карточке трекера, дате и первичной записи хранится в приватном реестре воркспейса, вне этого репозитория; правило ссылается только на букву. Прошлые строки не переписываются: ошибка — новая строка со ссылкой на старую.» Одна таблица:

```markdown
| Якорь | Id | Симптом | Следствие | Правила |
```

### 6.4. Словари

`scripts/stop-words.txt` (публичный; одна POSIX ERE на строку; `#` — комментарий; **не содержит ни одного литерального имени**; границы слова — только переносимой конструкцией `(^|[^A-Za-z0-9_])` … `([^A-Za-z0-9_]|$)`, без `\b`, `\<`, `\>` и `-w`: это расширения GNU/TRE, POSIX ERE их не гарантирует, а сторож обязан давать один и тот же вердикт на GNU `grep` в CI и на BSD `grep` рабочей машины):

```
# идентификатор карточки трекера: 3–6 заглавных латинских букв, дефис, 1–6 цифр; граница слова — явными классами
(^|[^A-Za-z0-9_])[A-Z]{3,6}-[0-9]{1,6}([^A-Za-z0-9_]|$)
# то же в нижнем регистре (якоря, имена файлов)
(^|[^A-Za-z0-9_])[a-z]{3,6}-[0-9]{1,6}([^A-Za-z0-9_]|$)
# UUID
[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}
# e-mail
[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}
# URL GitHub (в публичном дереве адреса — только плейсхолдерами)
github\.com/
# ссылка на PR чужого репозитория вида владелец/репозиторий#N
[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+#[0-9]+
```

`scripts/stop-words-allow.txt` — токены, которые совпадают со структурными шаблонами, но разрешены; один литерал на строку, без регулярных выражений: `UTF-8`, `ISO-8601`, `SHA-256`, `SHA-1`, `POSIX-1`; пополняется PR, когда сторож краснеет на законном токене. Сторож вырезает разрешённые токены из строки **до** прогона шаблонов (§6.5, шаг 0), а не сравнивает извлечённые совпадения после: с явными классами границы совпадение захватывает соседний символ-разделитель, и точная сверка `grep -vxF` дала бы ложный красный на ` UTF-8 `. Шаблон в нижнем регистре ловит и числовые якоря (`inc-` + цифры) — поэтому якоря инцидентов буквенные (`inc-b`), а не числовые.

`pm-workflow/stop-words-private.txt` (приватный реестр; тот же формат) — литералы по чек-листу владельца из тела подзадачи и по строкам приложения А, которые исполнитель читает в архивном дереве. Обязательные классы строк (исполнитель заполняет значениями): четыре префикса карточек — голым словом и с дефисом, в обоих регистрах; название проекта-источника (латиницей, в обоих регистрах); название трекера проекта (кириллицей и латиницей); название воркспейса (в двух написаниях); учётная запись GitHub владельца; имена трёх приватных репозиториев как пути и как слова; имя файла уроков проекта; имена шести известных агентов (полностью и по отличительному слову); имя владельца (латиницей и кириллицей); домен почты; имя подписки провайдера; короткий id рантайма. Порог: не меньше 20 непустых строк — сторож проверяет число, не содержимое. Кириллица: оба регистра явно (`[Пп]…`), потому что `grep -i` для кириллицы зависит от локали; CI — `LC_ALL=C.UTF-8`.

### 6.5. Сторож (`scripts/check-rules.sh`, критерий 4 → «стоп-слова», метка `[CI: check]`)

Замена нынешнего критерия 4 (каждый идентификатор `ПРЕФИКС-N` резолвится — после обезличивания идентификаторов нет). Новый критерий 4:

0. Фильтр (одна функция, применяется на шагах 2–5 к каждой строке входа): сначала вырезать разрешённые токены — `sed -E 's/(^|[^A-Za-z0-9_])(<allow-литералы через |, спецсимволы экранированы>)([^A-Za-z0-9_]|$)/\1\3/g'`, повторяя, пока вывод меняется (при подряд стоящих разрешённых токенах `UTF-8,SHA-1` один проход вырезает только первый: разделитель уже поглощён); затем `grep -nE -f <шаблоны>` по очищенной строке. Любое совпадение — `FAIL`. Нумерация строк не меняется (`sed` построчный). `--show` печатает совпавший фрагмент (`grep -noE`) — только локально.
1. Собрать шаблоны: `scripts/stop-words.txt` (пустые и `#`-строки отброшены) + приватный файл из `STOP_WORDS_PRIVATE_FILE` либо переменной окружения `STOP_WORDS_PRIVATE` (многострочный текст; в CI — из секрета). Если ни файла, ни переменной нет: при `CI=true` — `FAIL: private stop-word list missing`; локально — `WARN` и проверка только публичной частью. Если приватный список короче 20 строк — `FAIL`.
2. Дерево: для каждого файла из `git ls-files` (кроме самих `scripts/stop-words.txt`, `scripts/stop-words-allow.txt`) — фильтр шага 0 → `FAIL: stop-word <public|private>#<номер шаблона> at <файл>:<строка>`. Текст совпадения не печатается.
3. Имена файлов: `git ls-files` через фильтр шага 0 → `FAIL: stop-word in path #<n>`.
4. Диапазон PR (только когда заданы `PR_TITLE` и `PR_BASE_SHA`): `printf '%s\n' "$PR_TITLE"` и `git log --format=%B "$PR_BASE_SHA"..HEAD` через тот же фильтр → `FAIL: stop-word in PR title` / `in commit message <sha>`.
5. История (только `--history`, вызывается отдельным шагом CI): `git log --all -p --format='commit %H'` через фильтр шага 0 → `FAIL: stop-word in history, commit <sha>` (номер строки патча, без текста). Также `git log --all --format='%an %ae %cn %ce'` через фильтр — e-mail и имена авторов (§12, В3).

Вывод сторожа никогда не содержит совпавший текст — только координаты и номер шаблона. Сообщение при `FAIL` заканчивается подсказкой: `run locally: bash scripts/check-rules.sh --show`.

### 6.6. `.github/workflows/check.yml`

```yaml
name: check
on: [pull_request, push]
jobs:
  check:
    runs-on: ubuntu-latest
    env:
      LC_ALL: C.UTF-8
      STOP_WORDS_PRIVATE: ${{ secrets.STOP_WORDS_PRIVATE }}
      PR_TITLE: ${{ github.event.pull_request.title }}
      PR_BASE_SHA: ${{ github.event.pull_request.base.sha }}
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - name: check-rules (внутри — build-skills.sh --check и сторож стоп-слов)
        run: bash scripts/check-rules.sh
      - name: stop-words in history
        if: vars.SANITIZED_HISTORY == '1'
        run: bash scripts/check-rules.sh --history
      - name: parse-score-line self-test
        run: bash scripts/parse-score-line.sh --self-test
```

Имя job `check` не меняется (контракт `docs/required-checks.md`). Переменная репозитория `SANITIZED_HISTORY=1` ставится только в новом репозитории: в архивном история грязная по определению, и шаг пропускается — PR-A там зелёный по дереву. Секрет `STOP_WORDS_PRIVATE` заводит владелец (или PM по его слову) в обоих репозиториях: `gh secret set STOP_WORDS_PRIVATE -R <владелец>/<репозиторий> < pm-workflow/stop-words-private.txt`.

## 7. Заголовок PR в публичном репозитории

Правило `pipeline.md#pr-slug` (слаг карточки в заголовке PR) не меняется — это методика для репозиториев проектов. Для этого репозитория форма слага — проектная конвенция (слой 3 самого репозитория) и с публикацией меняется: префикс трекера в заголовок не пишется, только номер: `<type>(<scope>): <суть> (card N)`. Связь PR ↔ карточка сохраняется (номер уникален в трекере воркспейса), сторож на заголовок и сообщения коммитов не срабатывает. Записывается в `README.md` «Как править». Дефолт до ответа владельца — В2 (§12).

## 8. История git — процедура

Обоснование — ADR 0002. Порядок (после мержа PR-A и PR-B):

1. Владелец (или PM в чате по его слову; операции не PR): `gh repo rename <имя архива> -R <владелец>/pm-workflow` (дефолт имени — В1, §12) → `gh repo archive <владелец>/<имя архива> -y` → `gh repo create <владелец>/pm-workflow --private --description "регламент конвейера агентов"` → `gh secret set STOP_WORDS_PRIVATE -R <владелец>/pm-workflow < …` → `gh variable set SANITIZED_HISTORY -b 1 -R <владелец>/pm-workflow`. Порядок важен: переименование до создания, иначе имя занято; секрет и переменная до первого push, иначе первый прогон `check` красный.
2. Builder (второй прогон стадии кода): из checkout архива на `main` после мержа PR-A — `git archive --format=tar HEAD | tar -x -C <новый каталог>`; в нём `git init -b main`; `git config --worktree`-эквивалент для нового каталога: `git config user.name` как настроено, `user.email` — по В3; `git add -A` (без него `git commit` в пустом репозитории завершается exit 1: `nothing added to commit but untracked files present`); один коммит `docs: регламент конвейера агентов — обезличенный публичный репозиторий (card N)`; готово, когда `git log --oneline --all | wc -l` = 1 и `git status --porcelain` пуст; `git remote add origin <URL нового>`; `git push -u origin main`. Проверить: `gh run list -R <владелец>/pm-workflow --limit 1` → `check` зелёный (одна проверка без `--watch`; красный — `blocked` с выводом).
3. Владелец: branch protection на `main` с required check `check` (как было: strict, без force-push) — после первого зелёного прогона.
4. Builder: `multica repo checkout <URL> --fresh`; `git -C <checkout> log --oneline --all | wc -l` = 1. Больше одного — кэш воркспейса держит старую историю: `multica repo remove --url <URL>`, `multica repo add --url <URL> --description pm-workflow`, повторить checkout. Не помогло — `blocked`, операция владельца на машине воркспейса.
5. Builder: в новом checkout `STOP_WORDS_PRIVATE_FILE=<путь к приватному словарю> bash scripts/check-rules.sh --history` → 0 ошибок; отчёт в карточку с командами и числами.

Стоимость: владелец ~20 минут (шаги 1, 3); Builder ~1 час (шаги 2, 4, 5). Альтернатива «force-push в тот же репозиторий» стоила бы меньше (без шага 1), но не даёт гарантии — ADR 0002.

## 10. Критерии приёмки

Машинные (`scripts/check-rules.sh`, job `check`, `[CI: check]`):

1. Сторож стоп-слов (критерий 4 новый): 0 совпадений по дереву, именам файлов, заголовку PR и сообщениям коммитов диапазона — с приватным словарём из секрета; без словаря в CI — красный.
2. В новом репозитории: `bash scripts/check-rules.sh --history` → 0 (шаг `stop-words in history`, переменная `SANITIZED_HISTORY=1`); в том числе авторы коммитов.
3. Критерии 1–3, 5–10, 18–21 прежней постановки без изменений — зелёные: `rules in index: 70` (число правил не изменилось), `incident rows in resolver: 24`, `changelog entries: 15`, `gotchas: section A 13 items, section B 7 items`.
4. Приватный словарь ≥ 20 строк (проверяет сторож числом).
5. `docs/incidents.md`: у каждой строки непустые столбцы «Симптом», «Следствие», «Правила» (awk по `|`-разделителям, пустая ячейка — `FAIL`).

Руками (аудитор стадии кода и владелец):

6. Каждая строка приложения А обработана по своему действию; ни одна строка вне приложения А в файлах правил не изменилась по смыслу — аудитор читает `git diff` PR-A построчно против приложения А: дифф в `docs/{roles,pipeline,review-cycle,impact-class,ownership}.md` затрагивает только строки приложения А и строки-ссылки на удалённые файлы.
7. Каждое правило сохранило основание: для каждой строки `Инцидент: [X](incidents.md#inc-x)` публичная строка X содержит симптом и следствие, из которых правило выводится без чтения приватной таблицы.
8. Каждый пункт раздела A слоя 1 сохранил условие снятия (критерий 6 держит наличие; смысл — глазами).
9. Приватная таблица: 30 строк соответствий + 9 решений; каждая буква A–X ровно один раз; каждый UUID из архивного `CHANGELOG.md` и ADR 0001 найден в таблице решений (`grep -c` по каждому — в отчёте числами).
10. `git ls-files` нового репозитория не содержит `docs/archive/`, `workspace-notes.md`, исходной постановки; `git log --oneline --all | wc -l` = 1.
11. Владелец читает публичное дерево целиком до перевода в public — он единственный, кто знает полный список имён; найденное имя — строка в приватный словарь, секрет, PR; если имя ушло в историю нового репозитория — повтор §8 (новый репозиторий), не force-push.
12. Чего машина не проверяет: полноту приватного словаря; что обезличенный симптом не потерял смысл; что столбец «Правила» резолвера полон; что владелец обновляет секрет при новом имени — `[ревью: владелец @ приёмка]`.

## 11. Риски и радиус поражения

| Риск | Что ломается | Смягчение |
|---|---|---|
| Приватный словарь неполон — имя уходит в public | утечка одного имени | критерий 11 (чтение владельцем до публикации); каждая строка словаря обязана что-то ловить в архиве (B2) — словарь строится от фактов, не от памяти; повтор §8 при утечке в историю |
| Структурный шаблон `[A-Z]{3,6}-[0-9]+` ловит законные токены | ложный красный на PR | `stop-words-allow.txt` пополняется PR; шаблон не ослаблять |
| Секрет недоступен (PR из форка, секрет не заведён) | сторож красный | намеренно; сообщение называет причину; форков не ожидается |
| Логи Actions публичного репозитория показывают совпадения | утечка через лог | сторож печатает координаты и номер шаблона, не текст; `--show` — только локально; провокации A8 — в отчёт карточки, не в CI |
| Кэш checkout воркспейса держит старую историю после смены репозитория | `multica repo checkout` даёт старое дерево или падает | §8 шаг 4: `remove`/`add`; иначе владелец |
| Переименование старого репозитория ломает ссылки в постановках других проектов | ссылки вида `pm-workflow` без URL — не ломаются; URL с именем архива редиректится GitHub, пока новое имя не занято, — после создания нового репозитория URL ведёт на новый | это и нужно: адрес в реестре воркспейса и URL импорта скиллов остаются верными |
| Буква без таблицы ничего не говорит читателю | правило теряет доказательную силу | столбцы «Симптом»/«Следствие» (критерий 7); приватная таблица для владельца и PM |
| Два места на один инцидент | забыли приватную строку | процедура в README приватного каталога; PM проверяет на промоции PR с новым инцидентом |
| Builder «сжимает» правило, убирая имя | смысл меняется без CHANGELOG | критерий 6: дифф в файлах правил ограничен строками приложения А |
| E-mail автора в истории нового репозитория | персональные данные в public | В3, §12; сторож проверяет авторов в `--history` |

Радиус поражения при неверном решении «новый репозиторий»: ноль для конвейера — регламент доставляется скиллами, URL не меняется; при неудаче инициализации старый репозиторий продолжает жить как приватный архив, из него можно повторить экспорт. При неверном решении «буквы вместо идентификаторов»: правила читаются хуже, но не меняются; обратный переход — замена ссылок по приватной таблице одним скриптом.
