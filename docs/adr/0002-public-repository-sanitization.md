# ADR 0002 — обезличенный публичный репозиторий: новая история, приватный резолвер, двухчастный словарь стоп-слов

- Статус: предложено (стадия постановки, 2026-09-18); принимается решением владельца при приёмке родительской карточки.
- Автор: Architect. Аудит: Reviewer (один круг, класс `гигиена`).
- Постановка: `docs/superpowers/plans/2026-09-18-sanitize-pm-workflow.md` (в архивном дереве имя файла со слагом карточки — см. постановку, §5).
- Решение владельца о старте: 2026-09-18, реквизит D-9 в приватном реестре.

## Контекст

Слой доставки регламента (`multica skill import --url`) работает только с публичным GitHub. Репозиторий содержит внутреннюю кухню воркспейса: названия проектов и организаций, идентификаторы карточек трекера и комментариев, ссылки на приватные репозитории и документы, снимок инструкций PM, имена агентов и людей, детали инцидентов. Владелец решил (2026-09-18): публиковать только после обезличивания; временный импорт архивом отклонён. Инвентаризация: 260 строк в рабочем дереве (без собранной копии скилла) и 635 добавленных строк в истории из 11 коммитов содержат стоп-слова; чистого коммита в истории нет — конфиденциальное сидит в каждом.

## Решение

Три связанных решения.

**1. История: новый репозиторий с одним коммитом; старый — приватный архив.** Обезличенное дерево собирается PR в текущий (приватный) репозиторий, проходит аудит и CI, после мержа экспортируется (`git archive`) в новый пустой репозиторий одним коммитом. Старый репозиторий переименовывается и архивируется (read-only), остаётся приватным; новый получает прежнее имя, поэтому адрес в реестре воркспейса и URL импорта скиллов не меняются.

**2. Приватный резолвер.** Публичный `docs/incidents.md` хранит инциденты в обезличенной форме: буквенный id (`A`, `B`, … `Z`, `AA`, …), якорь `inc-<id>`, симптом, следствие, правила, которые на него опираются. Соответствие «буква ↔ карточка, дата, первичная запись» и реквизиты решений владельца (`D-N` ↔ карточка, комментарий) хранятся в приватном реестре воркспейса, вне публичного репозитория. Правила и пункты слоя 1 ссылаются только на буквы; строки `Решение:` в `CHANGELOG.md` — на дату и `D-N`.

**3. Двухчастный словарь стоп-слов и сторож.** Публичная часть (`scripts/stop-words.txt`) — только структурные шаблоны: формат идентификатора карточки трекера (`ПРЕФИКС-N`), формат UUID, формат e-mail, URL GitHub. Приватная часть (литеральные названия проектов, организаций, репозиториев, агентов, людей, коротких id) лежит в приватном реестре и подаётся в CI секретом репозитория. Сторож в `scripts/check-rules.sh` проверяет дерево, имена файлов, заголовок PR и сообщения коммитов диапазона PR, а в новом репозитории — всю историю; любое совпадение — non-zero с `файл:строка` и номером шаблона, без вывода совпавшего текста (логи Actions публичного репозитория читают все).

## Рассмотренные альтернативы

**История А. `git filter-repo` по словарю с force-push в тот же репозиторий (branch protection снять и вернуть).** Отвергнуто по трём причинам. (1) GitHub не удаляет коммиты при force-push: старые SHA остаются достижимы через `refs/pull/N/head` трёх смерженных PR и по прямой ссылке; чистка требует обращения в поддержку GitHub и не проверяется изнутри воркспейса. После перевода в public утечка по старому SHA — это именно то, чего избегаем. (2) Замена по словарю в 11 коммитах, где каждый коммит содержит стоп-слова (635 строк), даёт историю, в которой исходная постановка и снимок инструкций всё равно описывают внутреннюю работу — смысл текста замена не убирает. Ценность такой истории для публичного читателя нулевая. (3) Кэш checkout воркспейса и рабочие копии агентов держат старые SHA; после force-push каждая рабочая копия расходится с `origin`. Критерий выбора — «утечка невозможна по построению, а не по дисциплине» — не выполняется.

**История Б. Orphan-ветка и force-push в тот же репозиторий.** Дешевле А (без `filter-repo`), но та же причина (1): старые коммиты остаются достижимы через PR-refs. Отвергнуто.

**История В (принято). Новый репозиторий.** Единственный вариант, при котором в публичном репозитории физически нет ни одного объекта со стоп-словами. Цена: операции владельца (переименование, создание, секрет, переменная, branch protection — около 20 минут), перерегистрация кэша checkout в воркспейсе, потеря публичной истории трёх PR (она остаётся в приватном архиве).

**Вариант В′. Новый репозиторий под другим именем, старый не переименовывать.** Отвергнуто: меняются адрес в реестре воркспейса, URL импорта обоих скиллов, тексты автопилотов и заметок; переименование старого репозитория до создания нового с прежним именем снимает всё это одной операцией.

**Резолвер А. Оставить идентификаторы карточек, убрать только названия проектов.** Отвергнуто: префикс идентификатора — имя проекта/воркспейса (владелец включил префиксы в чек-лист конфиденциального явно); идентификатор без префикса — число без смысла для читателя, но и без пользы для правила. Правилу нужны симптом и следствие, а не номер.

**Резолвер Б. Дата как публичный ключ инцидента.** Отвергнуто: у пяти инцидентов прежнего воркспейса точной даты нет; два инцидента приходятся на один день; дата — деталь деятельности организации (сроки), а буква — нет.

**Резолвер В (принято). Буквенный id + приватная таблица соответствий.** Один адрес на инцидент, переживающий и переезд воркспейса, и публикацию.

**Словарь А. Один публичный файл с литеральными названиями.** Отвергнуто: словарь сам стал бы утечкой — публичный файл с именами проектов, организаций и людей. Это противоречие в исходной постановке стадии (словарь «названия проектов» в публичном репозитории); снимается разделением.

**Словарь Б. Полностью приватный словарь, сторож только локальный.** Отвергнуто: сторож без CI — дисциплина, а не гейт; правило `[CI: check]` требует машинной проверки на каждом PR.

**Словарь В (принято). Публичные структурные шаблоны + приватные литералы секретом CI.** Секреты недоступны PR из форков — для них сторож красный с сообщением «приватный словарь не подан»; PR в этот репозиторий делают только агенты воркспейса, форков не ожидается.

## Последствия

- Плюс: в публичном репозитории нет объектов со стоп-словами по построению; сторож держит это на каждом PR и по всей истории; регламент сохраняет доказательность (симптом · следствие · правило) без раскрытия карточек.
- Минус: два места для одного инцидента (публичная строка + приватная строка) — при добавлении инцидента нужны два PR; приватный словарь — секрет, который владелец обновляет руками при появлении нового имени; буква инцидента ничего не говорит читателю без таблицы — компенсируется столбцами «Симптом» и «Следствие».
- Радиус поражения при неверном решении: если приватный словарь неполон — одно имя уходит в public; обнаруживается чтением при приёмке владельцем (он единственный, кто знает полный список имён), лечится PR и новым секретом; история нового репозитория при этом снова грязная — тогда повтор операции «новый репозиторий» (та же цена, 20 минут владельца). Если кэш checkout воркспейса не переживает смену истории — `multica repo remove`/`add`; не помогает — операция владельца на машине воркспейса.

## Что проверяет, что решение работает

(1) В новом репозитории `git log --all -p` по объединённому словарю даёт 0 совпадений — команда в отчёте стадии кода. (2) Сторож даёт красный на четыре провокации (стоп-слово в файле, в имени файла, в заголовке PR, в сообщении коммита) — команды и вывод в отчёте. (3) Через 30 дней после публикации: импорт и `refresh` обоих скиллов работают с публичного URL; ни одного PR в публичный репозиторий не закрыто по красному сторожу из-за ложного срабатывания структурных шаблонов (иначе — расширить `scripts/stop-words-allow.txt`, не ослаблять шаблон).
